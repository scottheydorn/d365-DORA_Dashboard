📋 Executive Summary

The Challenge

Implementing DORA metrics for D365 Finance & Operations presents unique challenges because DORA was designed for Git-based CI/CD workflows. D365 F&O environments typically use TFVC repositories, require LCS for deployments, and follow longer release cycles than typical DevOps implementations.

Key Challenges Addressed

TFVC Correlation

No pull requests or merge events to track. Requires explicit changeset → build → deployment tracing.

LCS API Complexity

AAD authentication requirements and limited API surface for deployment history extraction.

Multi-Environment Tracking

Dev, Test, UAT, and Production environments across multiple LCS projects need unified visibility.

💡
Recommended Strategy

Use Work Items as the unit of change rather than individual changesets. A single PBI/Bug may have multiple changesets, and Lead Time should measure from the first changeset linked to a work item until the deployment containing all linked changesets reaches Production.

🏗️ Architecture Overview

The recommended architecture uses Azure Functions for data collection and DORA calculation, Azure SQL for storage, Logic Apps for Teams notifications, and Power BI for visualization.

Why This Pattern?

✅
Advantages

Code-first approach handles complex TFVC correlation logic. Azure Functions consumption plan keeps costs low (~$50/mo). Full control over data model and calculations.

⚠️
Alternative Considered: Power Automate

Premium connectors required (~$15/user/mo). Limited ability to handle complex changeset→deployment correlation. Harder to version control.

📊 DORA Metrics Implementation

The four key DORA metrics adapted for D365 Finance & Operations environments:

Metric D365 F&O Implementation Elite High Medium Low
Deployment Frequency LCS deployments to Production environment Multiple/day Daily-Weekly Weekly-Monthly Monthly+
Lead Time for Changes Changeset creation → Production deployment < 1 day < 1 week < 1 month > 1 month
Change Failure Rate Failed + rolled-back deploys / total deploys < 15% < 30% < 45% > 45%
Mean Time to Recovery Incident detection → Service restoration < 1 hour < 1 day < 1 week > 1 week
📝
D365 Reality Check

Most D365 F&O implementations will fall into the Medium or Low tiers for Deployment Frequency due to the platform's testing requirements and release cadence. This is expected and acceptable—the goal is to measure and improve over time, not achieve Elite status on day one.

Metric Calculation Examples

SQL: Deployment Frequency Query
SELECT 
    DATEPART(week, deployment_date) AS week_number,
    COUNT(*) AS deployment_count,
    CASE 
        WHEN COUNT(*) >= 7 THEN 'Elite'
        WHEN COUNT(*) >= 1 THEN 'High'
        WHEN COUNT(*) >= 0.25 THEN 'Medium'
        ELSE 'Low'
    END AS performance_tier
FROM dora.deployments
WHERE environment_tier = 'Production'
    AND status = 'Succeeded'
    AND deployment_date >= DATEADD(month, -3, GETDATE())
GROUP BY DATEPART(week, deployment_date)

Correlation Challenges & Solutions

What TFVC Provides Natively

  • Changeset → Work Item links (associated work items)
  • Changeset ID in build SourceVersion field
  • Build artifacts with consistent naming patterns
  • Build timeline and history

Manual Correlation Required

  • Build artifact → LCS Asset Library mapping
  • Naming convention or metadata tagging strategy
  • Asset ID → Deployment reference linking
  • Cross-environment deployment tracking

Correlation Engine Logic

Python: Correlation Engine
async def correlate_changeset_to_deployment(
    self, 
    changeset_id: int
) -> Optional[DeploymentCorrelation]:
    """
    Trace changeset through the deployment pipeline.
    
    Correlation chain:
    1. Changeset → Work Items (native ADO links)
    2. Changeset → Build (SourceVersion field)  
    3. Build → Artifact (deployable package)
    4. Artifact → LCS Asset (naming convention)
    5. Asset → Deployment (LCS API)
    """
    
    # Step 1: Get changeset and linked work items
    changeset = await self.ado.get_changeset(changeset_id)
    work_items = await self.ado.get_changeset_work_items(changeset_id)
    
    # Step 2: Find builds containing this changeset
    builds = await self.find_builds_with_changeset(changeset_id)
    
    if not builds:
        return None
    
    # Step 3: Get deployable packages from builds
    artifacts = []
    for build in builds:
        build_artifacts = await self.ado.get_build_artifacts(build.id)
        artifacts.extend([a for a in build_artifacts if a.name.endswith('.zip')])
    
    # Step 4: Match to LCS assets
    lcs_assets = await self.match_artifacts_to_lcs_assets(artifacts)
    
    # Step 5: Find deployments using those assets
    deployments = await self.lcs.get_deployments_by_assets(lcs_assets)
    
    return DeploymentCorrelation(
        changeset=changeset,
        work_items=work_items,
        builds=builds,
        assets=lcs_assets,
        deployments=deployments
    )

⚙️ Component Details

Azure DevOps Client

Collects TFVC changesets, work items, and build data from Azure DevOps REST APIs.

  • GET /_apis/tfvc/changesets
  • GET /_apis/wit/workitems
  • GET /_apis/build/builds
  • GET /_apis/build/builds/{id}/artifacts

LCS API Client

Collects deployment history and environment status from Lifecycle Services.

  • GET /api/environments/v1/{projectId}
  • GET /api/deploymenthistory/v1/{projectId}/{envId}
  • GET /api/assetlibrary/v1/{projectId}
  • AAD OAuth2 authentication required

Azure Functions

Python-based data collection running on consumption plan with timer triggers.

  • ADO Collector - Changesets, WIs, Builds
  • LCS Collector - Deployments, Environments
  • Correlation Engine - Links CS→Build→Deploy
  • DORA Calculator - Metrics computation

Azure SQL Database

Central storage for all metrics, correlations, and historical data.

  • dora.changesets - TFVC check-ins
  • dora.deployments - LCS deployment history
  • dora.correlations - CS→Deploy links
  • dora.metrics_daily - Pre-calculated DORA

Power BI Dashboard

Single pane of glass for DORA metrics and environment status visualization.

  • DORA Metrics Overview
  • Deployment Frequency Trends
  • Lead Time Distribution
  • Environment Health Matrix
  • Drill-through to Changesets

Teams Notifications

Proactive alerts via Logic Apps using Adaptive Cards.

  • Daily DORA summary (scheduled)
  • Deployment failure alerts
  • DORA tier degradation warnings
  • Environment health changes
